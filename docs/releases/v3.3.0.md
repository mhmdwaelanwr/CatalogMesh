# CatalogMesh v3.3.0

CatalogMesh v3.3.0 is the first stable release using the **CatalogMesh** desktop display brand. The published Python package remains `ai-product-photo-sorter`, and the existing `product-sorter-*` commands and `PRODUCT_SORTER_*` settings remain supported through the v3.x compatibility line.

This release turns the v3.2 local catalog pipeline into a fuller day-to-day catalog workspace: a 12-workspace desktop, tested GUI/CLI parity, bounded rclone storage operations, stronger human-approval controls, and connector-specific Shopify, Akeneo, and Odoo execution paths.

## Highlights

### CatalogMesh desktop and CLI parity

- Canonical 12-workspace desktop flow: Operation setup → Models & API keys → Results & activity → Review → SKU Match → Exports → Storage → Automation → Reports → Benchmark → Environment → About.
- First-class `catalogmesh`, `catalogmesh-gui`, `catalogmesh-config`, `catalogmesh-reports`, `catalogmesh-storage`, `catalogmesh-automation`, `catalogmesh-watch`, and `catalogmesh-mcp` aliases while retaining the established `product-sorter-*` commands.
- Parser-driven Automation Center and a capability parity registry that CI uses to keep the desktop, CLI, and shared bounded backends aligned.
- English, Arabic, and Chinese runtime translation coverage, including Arabic shaping/BiDi compatibility where native Tk rendering is incomplete.
- Responsive workspace navigation and long-workspace scrolling without re-parenting Tk notebook pages.
- Packaged-Windows light/dark documentation captures for every workspace, with visual-noise filtering to avoid meaningless CI screenshot churn.

### Storage Center · rclone

CatalogMesh v3.3.0 adds a local-first Storage Center and terminal surface for existing rclone remotes:

- version and remote discovery;
- read-only connectivity testing;
- dry-run preview;
- Copy;
- manually confirmed Sync mirror;
- bandwidth, transfers, and checkers controls;
- live output and cancellation.

Automatic post-sort transfer is always **Copy-only**. Manual mirror operations require the exact `SYNC <full-target>` phrase. CatalogMesh does not start rclone's RC HTTP server, parse/own the rclone credential file, expose a generic storage executor, or expose storage mutation through MCP.

### Human-approved automation and connectors

- Human-only external-action approval artifacts; agents/MCP may request or validate approval state but cannot approve their own action.
- Atomic approval records, single-use execution reservations, deterministic idempotency identities, bounded retry metadata, and append-only redacted execution audit evidence.
- Recursive rejection/redaction of credential-like fields in approval/execution payloads.
- Shopify draft staging behind an approved reservation, with staged products kept DRAFT/unpublished.
- Shopify publication and publication rollback each require a separate approval/reservation; staging approval cannot publish.
- Zero-network PIM/ERP connector profiles and write plans with no embedded credentials and no generic connector executor.
- Akeneo product execution, read-only reconciliation, separately approved rollback, pre-write snapshots, and fresh remote-drift fingerprint checks before rollback.
- Odoo existing-product updates by `default_code` with a bounded field set, full preflight, read-only reconciliation, and no create/delete path.

## Reliability improvements

- Frozen desktop configuration now persists to stable per-user configuration locations instead of PyInstaller `_MEI...` temporary extraction directories.
- An existing `.env` beside the packaged executable continues to opt into portable mode.
- Current `google-genai` 2.x is supported through `google-genai>=2.21,<3` and has been exercised across the repository's tests, safety workflows, platform packaging, and packaged Windows GUI smoke.

## Safety model retained

CatalogMesh v3.3.0 deliberately does **not** turn AI suggestions into catalog identity or publication authority:

- SKU/catalog matches remain human-confirmed.
- External publication remains explicit and action-specific.
- Partial or ambiguous writes fail closed into reconciliation rather than blind retries.
- Credentials stay in environment/keyring configuration and are not placed in approval payloads or execution logs.
- MCP exposes no generic remote mutation, publish, rollback, or rclone transfer executor.

Local approval artifacts provide workflow integrity checks but are not cryptographic signatures against a hostile local user.

## Verification boundary

The release pipeline verifies unit and integration behavior, CodeQL and connector safety gates, Linux/Windows/macOS packaging, Python distributions, artifact download integrity, and the packaged Windows GUI smoke flow.

Real paid-provider samples and real Shopify/Akeneo/Odoo service writes still depend on the owner's credentials and service environment. Treat those as environment-specific production verification; this release does not claim that a third-party production store/PIM/ERP was modified by CI. Representative labelled product-shoot data is also still required before publishing real-world accuracy claims or enabling any future production Hybrid Routing decision.

## Release artifacts

The GitHub Release includes:

- Windows x64 packaged desktop application;
- Linux x64 standalone package and Debian package;
- macOS Apple Silicon (`arm64`) application;
- macOS Intel (`x86_64`) application;
- Python wheel and source distribution;
- `SHA256SUMS.txt` checksums.

The Python package is published as **`ai-product-photo-sorter==3.3.0`** to PyPI through GitHub OIDC Trusted Publishing.

Desktop binaries are not currently code-signed/notarized, so Windows or macOS may show the normal warning for an unsigned open-source application.
