# Security Policy

## Supported versions

Security fixes target the latest stable release line.

| Version | Supported |
|---|---|
| 3.1.x | Yes |
| Older versions | Best effort only |

## Reporting a vulnerability

Please report security vulnerabilities privately. Use GitHub's **Security** tab and private vulnerability reporting when that option is available for this repository.

If private reporting is unavailable, open a minimal public issue asking the maintainer for a private contact path **without** including exploit details, credentials, private product images, file-system paths, or other sensitive information.

Please include, privately where appropriate:

- A short description of the issue and its impact.
- The affected version and platform.
- Reproduction steps or a minimal proof of concept.
- Any suggested mitigation, if known.

Do not test against systems, accounts, API keys, or data you do not own or have permission to use.

## Exposed credentials

If an API key or other credential may have been exposed, revoke it immediately at the provider and create a replacement. Removing a secret from Git history does not make that credential safe again.
